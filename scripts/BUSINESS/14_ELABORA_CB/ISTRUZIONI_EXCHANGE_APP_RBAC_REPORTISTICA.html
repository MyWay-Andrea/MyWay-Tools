Exchange App RBAC

Configurazione dell'invio Graph limitato alla mailbox reportistica@mywaysrl.it

Obiettivo. Consentire all'app Microsoft Entra usata da 14_ELABORA_CB di inviare report tramite Microsoft Graph solo dalla mailbox indicata.

La configurazione e' nel cloud Microsoft 365 / Exchange Online. I comandi possono essere eseguiti da un PC qualsiasi, ma usando un account con gli adeguati privilegi Exchange e Microsoft Entra.

Chi deve eseguirla

Normalmente l'amministratore Microsoft 365 / Exchange. Puo' operare dal proprio PC o dal PC del tecnico; non e' necessario essere amministratore locale del PC.

L'account deve poter gestire le assegnazioni App RBAC. Microsoft indica normalmente il ruolo Entra Exchange Administrator e un'assegnazione delegante in Exchange, tipicamente tramite Organization Management.

Dati dell'app precompilati

Questi sono i valori dell'app ELABORA CB - Invio Report, inseriti per l'amministratore che eseguira' la configurazione:

Valori da usare
Application (client) ID         : 977573f0-d883-4258-9ffe-56db725888da
Tenant ID                       : 1ea73f05-81a0-46d3-9cb1-9a3ccd1752e9
Enterprise application Object ID: a99728dd-4527-4db0-88bf-2ad7bbeb3784
Mailbox mittente                : reportistica@mywaysrl.it

L'Object ID usato da Exchange e' quello dell'Enterprise application, non quello di App registrations. Il client secret non e' riportato qui: non serve alla configurazione RBAC e non va inoltrato in un file condiviso.

Attenzione ai permessi globali

App RBAC assegna Application Mail.Send entro uno scope. I permessi Entra e le assegnazioni RBAC Exchange si sommano. Se l'app ha gia' il permesso globale Microsoft Graph > Application > Mail.Send, l'amministratore deve valutarne rimozione e revoca del consenso: altrimenti il limite alla sola mailbox non e' efficace. Non rimuoverlo se l'app e' usata da altri processi senza valutarne l'impatto.

Procedura

1. Verifica preliminare

  1. Verificare che reportistica@mywaysrl.it abbia una mailbox Exchange Online attiva.
  2. In App registrations > [app] > API permissions, verificare l'eventuale presenza di Microsoft Graph > Application > Mail.Send.

2. Collegamento a Exchange Online PowerShell

PowerShell — una sola volta se necessario
Install-Module ExchangeOnlineManagement -Scope CurrentUser
PowerShell — collegamento
Connect-ExchangeOnline

3. Impostare i valori

I valori sono gia' precompilati.

PowerShell
$appId = "977573f0-d883-4258-9ffe-56db725888da"
$entraServicePrincipalObjectId = "a99728dd-4527-4db0-88bf-2ad7bbeb3784"
$mailbox = "reportistica@mywaysrl.it"
$scopeName = "Scope-Graph-Reportistica"
$appName = "ELABORA CB - Invio Report"

4. Creare lo scope della sola mailbox

PowerShell — crea scope
New-ManagementScope `
  -Name $scopeName `
  -RecipientRestrictionFilter "PrimarySmtpAddress -eq '$mailbox'"
PowerShell — verifica scope
Get-Recipient -ResultSize Unlimited `
  -Filter (Get-ManagementScope $scopeName).RecipientFilter |
  Format-Table Name,PrimarySmtpAddress,RecipientType
Il risultato deve contenere soltanto reportistica@mywaysrl.it. Se contiene altri destinatari, fermarsi e correggere il filtro.

5. Creare o recuperare il service principal Exchange

PowerShell — creazione
New-ServicePrincipal `
  -AppId $appId `
  -ObjectId $entraServicePrincipalObjectId `
  -DisplayName $appName

Se esiste gia', non ricrearlo. Recuperarlo cosi' (eseguire anche dopo la creazione):

PowerShell — recupero
$exoSp = Get-ServicePrincipal -Identity $appId
$exoSp | Format-List DisplayName,AppId,ObjectId

6. Assegnare il solo diritto di invio

PowerShell
New-ManagementRoleAssignment `
  -Name "Graph-Reportistica-MailSend" `
  -App $exoSp.ObjectId `
  -Role "Application Mail.Send" `
  -CustomResourceScope $scopeName

Non assegnare Application Exchange Full Access: il ruolo minimo necessario e' Application Mail.Send.

7. Test di autorizzazione

PowerShell — mailbox autorizzata
Test-ServicePrincipalAuthorization `
  -Identity $exoSp.ObjectId `
  -Resource $mailbox

Per Application Mail.Send, il risultato deve indicare InScope : True.

PowerShell — mailbox non autorizzata
Test-ServicePrincipalAuthorization `
  -Identity $exoSp.ObjectId `
  -Resource "altra-mailbox@mywaysrl.it"

Qui il risultato deve indicare InScope : False.

8. Configurazione dello script

File .env
GRAPH_SENDER_EMAIL=reportistica@mywaysrl.it
EMAIL_DRY_RUN=true

Mantenere il dry-run durante il collaudo. Solo dopo il test positivo e dopo l'aggiornamento del codice a Graph, impostare EMAIL_DRY_RUN=false.

Stato dello script

Lo script usa Microsoft Graph: ottiene un token client-credentials e chiama POST /users/reportistica@mywaysrl.it/sendMail. Prima del primo invio reale mantenere EMAIL_DRY_RUN=true, verificare la simulazione e poi impostare EMAIL_DRY_RUN=false.
